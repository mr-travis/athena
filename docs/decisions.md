## 2026-11-17：工具执行终端记录

- 用户确认终端 JSON 日志方案；记录由 Athena 执行位置产生，不依赖模型自述，不更改 HTTP 响应或持久化日志文件。
- 程序生成每轮随机 request_id，记录 step、白名单工具名/unknown、status、duration_ms 和失败类别 error_type。不记录路径、参数、正文、密钥、用户消息、模型 ID 或原异常。
- started 表示分发尝试开始；成功/失败/拒绝形成终态。参数和权限拒绝也计入原预算；多调用、无效协议和超预算在执行前只记 rejected，绝不因此执行额外工具。
- 耗时只含工具分发，不含模型请求；开始或执行前拒绝为 0。日志仅为观察信息，不是任务持久化或恢复机制。
- 意外工具异常输出固定 InternalToolError 并映射固定 HTTP 500，避免原异常被 ASGI 输出；正常预期错误仍按既有结构化结果处理。

## 2026-11-17：目录与读取接入有上限的执行循环

- 用户确认每轮最多两次工具尝试、三次模型请求；不强制先列目录，支持普通问答直接结束。
- 首两次请求开放 `read_file` 与 `list_directory`，每次只接受一个调用；第三次不声明工具且显式禁用。多个调用整批拒绝，无第三次工具执行。
- 失败、非法参数、未知工具均消耗工具预算。校验工具调用 ID 不重复，并完整保存每次请求与对应结果的历史；无跨 HTTP 请求记忆。
- `read_file` 必须传相对 `path`；`list_directory` 可省略，默认 `.`。后端原权限、100 条上限、64 KiB 上限保持。
- 提示词要求多候选不明确时询问用户、预算耗尽时如实说明未完成操作，目录名与正文均不能成为新增授权。
- 沿用 `message`/`reply` 接口；任意次上游错误沿用 502/504，目录错误转结构化反馈。每次模型超时 60 秒，无额外整轮超时；最多三个模型请求会增加额度与耗时。
- 未新增框架、流式、写入或记忆。真实验收暴露启动环境 SOCKS 代理缺少支持，补充运行依赖 `httpx[socks]`，将原开发依赖 httpx 合并至运行依赖；`uv sync` 成功且仅新增安装 `socksio==1.0.0`，锁文件同步。保留代理配置，重启服务后继续验收。53 项离线测试通过；本步真实验收结果见 progress.md。
